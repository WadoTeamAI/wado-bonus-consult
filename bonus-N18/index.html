ローンチ当日 役割表＆週間タイムライン

配信でものを売る「ライブ週」の7日間、誰が・いつ・何をするかを1枚の地図にします。1人で全部やる方のための最小版もセットです。

はじめに

複数日にわたる配信で商品を売る「ライブ週」は、当日になって一番崩れやすい工程です。盛り上げ役が決まっておらずチャットが静かになったり、前日の告知がないまま本番を迎えて無理な集客ペースになったり、台本の修正が本番週にずれ込みリハーサルが削られたり。わどはこうした失敗を何度も見てきました。

原因はいつも同じです。「誰が・いつ・何をするか」が1枚になっていないことです。「みんなで」「適宜対応する」という書き方は、誰も担当しないことと同じ意味になります。

この特典は、ライブ週7日間(配信前日から配信後日まで)を「時間×役割×タスク」でマス目に落とした表です。原則は4つです。

  1. 1マス1人: 表のすべてのマスに、担当を1人だけ書きます。「みんなで」「適宜」は禁止です
  2. 空白マス禁止: マスが埋まっていない時間帯を作りません
  3. 引き継ぎは定型文で: 「これ終わったから次お願い」を、毎回同じ形式で伝えます
  4. 配信者は止めない: 配信中の人は、通知もDMも見ません。トラブル対応は他の役割が引き取ります

チームで動く方はそのまま、1人で動く方は「全体の地図」の最小版を使ってください。

この特典の進め方

  • このページ自体が特典の本体です。次のライブ週の1週間前に丸ごとコピーして使ってください
  • Notionやスプレッドシートに複製すると、日付・時刻をご自身のスケジュールに書き換えやすくなります
  • 表の「役割」は人数分に合わせて統合してかまいません(合わせ方は「全体の地図」の最小版を参照)
  • 配信開始が20時以外の場合は、Day1の時刻をそのままスライドさせてください(例: 19時開始なら全時刻を1時間前倒し)
  • 初めてのライブ週では、表の8割が埋まっていれば十分です。抜けている2割は振り返りで足していきます

最初のゴール(今日やる1つ)

今日はこれだけをやってください。

  • [ ] ライブ週の初日(Day1)の日付を決め、7日〜8日さかのぼった「D-1」をカレンダーに書き込む

D-1が決まったら、「全体の地図」の表に沿って担当する役割を仮決めしてください。人数が決まっていない場合は、「最初に投げるプロンプト」でAIと一緒に考えてください。

全体の地図(何週で何が終わるか)

ライブ週は「D-1(前日)→Day1〜Day5(本番)→D+1(翌日)」の7〜8日間です。役割は9種類あります。

略称 責務の1行
配信 台本どおりに話を進める。配信ON〜OFFの間は本業のみに集中する
進行 機材操作・残り時間の合図・配信者への最小限の声かけ
実況窓口 参加者が集まる場での実況投下・チャット拾い・着席促進・課題促進
SNS X・Threads・ストーリーズへの実況投稿・引用への反応
配信文 ステップ配信・当日の直前配信・受信メッセージへの一次対応
申込対応 終盤の個別相談の受付・実施・決済リンクの送付
数字 着席数・離脱率・反応数を一定間隔で記録する
緊急対応 配信落ち・問合せ殺到・離脱急増への即応
自動化 定型の集計・下書き作成・共有ページの更新をAIに任せる

7日間の大きな流れは次のとおりです。

日 フェーズ この日が終わっている目印
D-1 準備日 リハーサル完了・機材確認済み・前日の告知投稿済み
Day1 本番(初回) 配信完了・数字を記録済み
中日 振り返り＋準備 課題促進・翌日の台本チェック完了
Day2〜Day4 本番(継続) 配信完了・数字を記録・(Day3以降)個別相談の準備開始
Day5 本番(最終) 配信完了・締切告知・個別相談の受付開始
D+1 締め 個別相談の実施・数字の確定・振り返り

配信の前後30分と配信中は、通常の3倍の解像度(15分刻み)で動きます。これを「ホットゾーン」と呼びます。

ゾーン 解像度 重要ポイント
配信前30分 15分刻み 着席数の監視・通信状態の最終確認・実況窓口が着席を促し続ける
配信中 15分刻み チャット拾い・SNS抜粋投稿・15分ごとの着席数記録
配信後30分 15分刻み 振り返り投稿の消化・実況窓口が感想を拾う・メッセージでのお礼配信

それ以外の時間帯は30分〜1時間刻みで十分です。

1人でも回せる最小版

9つの役割は、人数に応じて次のように統合できます。空白のマスを作らないことが最優先です。

人数 統合の仕方
1人 配信+進行+実況窓口+SNS+配信文+申込対応+数字+緊急対応を自分が担当。自動化(集計・下書き)はできる限りAIに渡す
2人 Aさん=配信+進行+申込対応、Bさん=実況窓口+SNS+配信文+数字+緊急対応。配信中はAさんを止めない分担にする
3人以上 元の9役割に近づける。配信者は必ず専任にし、それ以外を人数に応じて束ねる

1人で回す場合の注意です。

  • 配信中は「数字の記録」と「チャット拾い」を両立できません。合間(質問受付や休憩)にまとめて確認する時間を台本に組み込んでください
  • 緊急時の一次対応が自分しかいない場合は、「配信を止めてでも対応すべきこと」と「配信後でよいこと」を先に線引きしておいてください
  • 1人運用は、まず小規模な回で試してから広げることをおすすめします

タスク全文(表・チェックできる粒度)

時刻の目安 役割 タスク
朝 緊急対応+進行 メッセージ配信のテスト送信・配信機材のセットアップ・録画設定の確認
午前〜昼 配信+数字 通しリハーサル1回目(90分)・着席予測をシートに更新
午後 SNS+実況窓口 「明日〇時から」の予告投稿(必須項目)・コミュニティへの予告投下
午後〜夕方 配信+自動化+配信文 リハーサル2回目(締め重点)・前日チェックリスト実行・直前配信

D+1(最終日翌日)タイムライン

時刻の目安 役割 タスク

昼〜午後 SNS+配信文 余韻の投稿(参加者の感想の引用)・お礼配信(参加者向け・購入者向けで分ける)

必須項目(欠落させてはいけないもの)

過去のライブ週で実際に抜け落ちて痛手になったものを、欠落不可能な項目として固定しています。

  • [ ] D-1朝: メッセージ配信の迷惑判定テスト
  • [ ] D-1午後: 「明日〇時から」のSNS予告投稿(前日の集客投稿が抜けると無理なペースになります)
  • [ ] D-1午後: コミュニティ全体への予告投下
  • [ ] Day1の19:30: 「着席チェック」の促進
  • [ ] Day1の22:00: 振り返り・お礼の投稿(熱が冷める前に出す)

引き継ぎの定型フォーマット

役割の受け渡しは、毎回この形式で共有チャットに投下してください。

[引き継ぎ YYYY-MM-DD HH:MM]
From: {役割}
To: {次の役割}
完了: {タスク+成果物の場所・1行}
未完: {残タスク+締切}
判断メモ: {その場で決めた方針があれば1行}
次アクション: {3つまで}
詰まっている点: {なし or 内容}

15分たっても拾われない場合は担当者に直接声をかけ、30分たっても拾われない場合は全員に共有し、緊急対応が代わりに拾ってください。

詰まったときの組み替え方

誰かが動けなくなったときの、代わりの立て方です。

状況 一次の代わり 二次の代わり
進行役が不在 緊急対応が兼任 配信者が最小限だけ兼任(配信は止めない)
コミュニティ運営がパンク 数字担当が助ける 実況を減らし着席促進だけに絞る
SNS実況が遅れる 実況窓口が代わりに投稿 下書きをAIに任せ、投稿だけ人が行う
配信文の設定ミス 緊急対応が確認・修正 翌日の配信で埋め合わせる
配信が落ちる 進行役がバックアップに切替 緊急対応が原因特定・配信者は継続発話

役割には上流と下流があります。数字担当が止まると、SNSや申込対応まで連鎖して止まります。数字担当は必ず「人+AIの二重化」にしてください(下の「最新AI」章を参照)。

緊急時の対応順序は次のとおりです。どの場面でも、配信者は止めません。

  1. 配信が落ちたとき: 配信者は予備マイク等で発話継続→進行役が切替リンクを共有→緊急対応が原因特定→3分で戻らなければお詫びを発信
  2. 参加者側のトラブル(決済不可・アクセス不明など): 緊急対応が個別に一次対応し、配信の進行には影響させない
  3. 問合せが殺到したとき: 申込対応がAIの下書きで一次返信を量産し、込み入った案件は当日中〜翌日に返す
  4. 離脱が急に増えたとき(目安: 着席数が3割以上減る): 数字担当が即共有→配信者は継続→進行役が次の案内を前倒し検討

進捗の見方

数字担当が記録する項目です。スプレッドシートに次の列を用意してください。

列 内容 記録のタイミング
時刻 記録した時刻 配信中は15分ごと
着席数 その時点の視聴者数 配信中は15分ごと
離脱率 直前記録からの減少割合 着席数を記録するたび
反応数 案内やCTAへの反応(クリック・登録など) 案内を出すたび
課題提出率 その日の課題を提出した人の割合 中日・翌朝
申込数 個別相談・購入の申込件数 Day3以降、1日数回

読み方の目安です。

  • 着席数は「増える/横ばい/減る」の傾向だけを見れば十分です。細かい上下に一喜一憂しないでください
  • 離脱率が急に大きくなった回(目安3割以上)は、直前に何を話していたかをメモすると、次回の台本修正に使えます
  • 反応数は、案内を出してから15分後の値で比較すると効き目が分かりやすくなります

その日の終わりには「着席の最大値」「離脱が大きかった時間帯」「反応が良かった案内」の3行で共有してください。

最新AI(2026年9月時点)で任せられる行(取得日つき)

2026年9月3日、OpenAIが新しいモデル「GPT-6 Astra」を発表しました(取得日2026-09-06)。従来モデルとの違いは、画面の情報を読み取り、承認されたアプリを人間と同じ画面越しに操作できることです。公開ベンチマーク(OSWorld 2.0・PC操作の評価)では前モデルの65.7%から72.6%まで伸びています。

ライブ週の運用では、数字シートへの記録、共有ページ(進捗一覧・タイムライン)の更新、SNS投稿・配信文の下書き作成(投稿は人が最終確認)を任せられる可能性があります。

注意点は2つです。段階的に提供が広がっている最中で、プランに含まれていても自分の画面にまだ出ていないことがあります。丸ごと任せる前に試しておいてください。もう1つは、画面に映っているものをそのまま指示として読み取ってしまう可能性があることです(提供元が明記)。参加者のチャットをAIに読ませて自動操作させる場合は、映す範囲を絞ってから使ってください。

AIに数字担当を丸ごと任せず、「AIが下書き・人が確認して反映」の二段構えにしておくと安全です。

次の一手

この特典は「稼ぎ方より、稼ぐ順番」のSTEP3(SNSとローンチで規模を上げる)に当たります。最初の1件・自分のコンテンツがまだの方は、先にそちらを終えてください。

ローンチ規模に合わせた最適な割り振りは人によって変わります。面談では、あなた専用の1枚(特注のロードマップ)を一緒に作ります。

最初に投げるプロンプト

ライブ週の準備を始める前に、AI(ChatGPT・Gemini・Claudeのどれでも構いません)にこのプロンプトを投げてください。自分の人数に合わせた役割の割り振りが具体的になります。

あなたはライブ配信でものを売る「ローンチ週」の運営設計を手伝うアシスタントです。

私について:
- ライブ配信の日数:【例: 5日間】
- 開始日と開始時刻:【例: 来週の火曜 20:00〜】
- 一緒に運営できる人数:【自分1人／2人／3人以上】
- 今までの配信経験:【まったくの未経験／少し経験がある】

やってほしいこと:
1. 「配信・進行・実況窓口・SNS・配信文・申込対応・数字・緊急対応・自動化」の9役割を、
   私の人数に合わせてどう統合すればよいか提案してください
2. 提案した割り振りで、配信中に1人が2つ以上の作業を抱えていないか確認してください
3. D-1にやるべきことを、優先順位つきで5つまでに絞って教えてください

## 制約
- 断定的な成果や収入の予測はしないでください
- 私が書いていない人員・経験を勝手に補わないでください
- 分からないことは「分かりません」と答えてください

よくある失敗 7つと直し方

  1. 盛り上げ役が決まっておらず、配信中に静かになる 直し方: 実況窓口を配信前に必ず1人決め、「何もなくても15分に1回は投稿する」ルールを渡します。

  2. 前日の集客投稿がなく、残り日数で無理なペースが必要になる 直し方: D-1の「必須項目」どおり、前日の午後に予告投稿を必ず出します。

  3. 台本の修正が本番週にずれ込み、リハーサルの時間が削られる 直し方: 修正はD-1より前に締め切ります。本番週は大きな修正をせず微調整だけにとどめます。

  4. 役割の受け渡しが口頭だけで、誰が今何をしているか分からなくなる 直し方: 「引き継ぎの定型フォーマット」を必ず使い、共有チャットに残します。

  5. 配信が落ちたときの対応者が決まっておらず、配信者自身が対応してしまう 直し方: 緊急対応の役割を先に決め、「配信者は止めない」を全員で確認します。

  6. 配信直後の振り返り投稿を後回しにして、熱が冷めてから出す 直し方: Day1の22:00の「必須項目」どおり、終了30分以内に振り返り投稿を出します。

  7. 翌日に振り返りをせず、次の準備に移ってしまう 直し方: D+1夜の振り返りを先に行い、3点(良かった点・つまずいた点・次に試すこと)を記録に残します。

安全に使うための注意

  • この表は参加人数や売上を保証するものではありません。運営の抜け漏れを減らす目安として使ってください
  • 参加者の個人情報・決済情報は、AIツールに貼り付けないでください
  • 参加者の感想・実績を紹介する場合は、必ず本人の許可を取ってから公開してください
  • 告知や案内の文章は、誇張表現(断定的な収入表現、根拠のない「誰でも」等)を避けてください
  • 配信・通信のトラブルに備え、必ずバックアップの手段(予備の配信環境・予備のマイクなど)を用意してください
  • AIが出力した内容は、事実確認をしてから使ってください。特に数字・日程は自分で裏を取ります

つまずいたときに聞くプロンプト

人数が足りない、役割が決まらない、というときに使ってください。

私はライブ配信でものを売る「ローンチ週」の準備で止まっています。

状況:
- 今の日程:【例: D-1・Day1の前日】
- 決まっていないこと:【例: 実況窓口の担当がいない】
- 人数の制約:【例: 自分1人しかいない】

やってほしいこと:
1. 決まっていないことを、今日決められる小さな一歩に分解してください
2. その一歩を終えたら、次に何を決めればいいか1つだけ提示してください
3. 人手が足りない場合、削ってもよい作業と削ってはいけない作業を分けて教えてください

用語集

用語 意味
ライブ週 配信を軸に商品を売り出す、複数日にわたる期間
D-1 / D+1 本番初日の前日 / 本番最終日の翌日
ホットゾーン 配信前後30分と配信中、解像度を上げて動く時間帯
必須項目 過去の失敗をもとに、欠落させてはいけないと決めた作業
引き継ぎ ある役割から次の役割へ作業を渡すときの共有
実況窓口 コミュニティ内で実況・チャット拾い・着席促進を担う役割
CTA 参加者に取ってほしい次の行動を示す呼びかけ
離脱率 直前の記録から視聴者がどれだけ減ったかの割合
オンボーディング 購入・申込後、相手が最初の一歩を踏み出せるよう支援すること
最小版 9つの役割を、少人数でも回せるよう統合した割り振り

出す前の品質チェック(10項目)

D-1の夕方に、次の10項目を確認してください。

  1. 9つの役割すべてに、担当(または統合した担当)が決まっているか
  2. Day1の15分刻みタイムラインに、空白のマスがないか
  3. 必須項目5つの担当と時刻が決まっているか
  4. 引き継ぎの定型フォーマットを、全員が使い方を分かっているか
  5. 配信のバックアップ手段(予備のマイクなど)を用意したか
  6. メッセージ配信の迷惑判定テストを済ませたか
  7. 数字担当が記録するシートの列を、あらかじめ用意できているか
  8. 緊急時の対応順序を、担当者全員が知っているか
  9. 1人で回す場合、「止めてでも対応すべきこと」の線引きが決まっているか
  10. D+1の振り返りミーティングが、すでにカレンダーに入っているか

10項目のうち答えに詰まるものがあれば、D-1のうちに解消してください。

最終チェックリスト

ライブ週が終わったら、この3点を自問してください。

  • [ ] 7日間、空白のマスなく役割が埋まっていたか
  • [ ] トラブルが起きたとき、配信者を止めずに対応できたか
  • [ ] D+1の振り返りで、次のライブ週に活かせることを1つ以上言語化できたか

3つすべてに「はい」と言えたら、この表は目的を果たしています。次のライブ週では、今回の振り返りをもとに、表をあなた専用に更新して使ってください。
