Claude Code コンテキスト衛生 10ルール

Claude Codeがだんだん的外れになる原因の9割は「情報の入れすぎ」です。この特典を読み終えると、あなたの環境を「散らからない部屋」に保つ10のルールと、週1回の点検の回し方が身につきます。

はじめに

わどです。この特典は、Claude Codeを毎日使う人向けの「片付けの教科書」です。

最初の1週間は、Claude Codeはとても賢く感じます。noteの下書きも、Instagramのキャプションも、Xの投稿文も、指示すればすっと出てきます。ところが1か月、2か月と使い続けると、同じ指示をしても返ってくるものがだんだんズレていく。そんな経験はありませんか。

原因のほとんどは、Claude Code自体が弱くなったのではありません。あなたが積み上げてきた「会話履歴・設定ファイル・過去のやり取り」が増えすぎて、AIが毎回読む情報の量（これを「コンテキスト」と呼びます）が散らかってしまったからです。

わどはこれを「部屋の整理」に例えて考えています。引っ越したばかりの部屋はどこに何があるか一目で分かります。でも半年も掃除をせずに物を積み上げ続けると、必要なものを探すのに時間がかかり、そのうち何がどこにあるかも分からなくなります。AIのコンテキストも同じです。整理しないと、AI自身が「今どの情報を優先すべきか」を見失います。

AIマネタイズにClaude Codeを本格的に使うなら、この「散らからない部屋」を保つ技術は、プロンプトの上手さと同じくらい大事なスキルです。むしろ、長く使えば使うほど効いてくる技術だと言えます。

この特典の進め方

この特典は次の順番で読むことをおすすめします。

  1. まず「最初のゴール」を今すぐやる。所要時間は3分です
  2. 「1. なぜコンテキストは壊れるのか」で考え方を掴む
  3. 「2. 情報の4層構造」で、自分の環境がどうなっているかを照らし合わせる
  4. 「3. コンテキスト衛生 10ルール」を通しで読む（ここが本体です）
  5. 「4. 週次の見直し運用」を、今週のどこかの時間に予定として入れる
  6. あとは必要になったときに「よくある失敗」「安全に使うための注意」「用語集」を辞書として使う

一気に全部を実践しようとしなくて大丈夫です。10ルールのうち、まず3つだけ今週やってみる。それで十分に変化を感じられるはずです。

最初のゴール（今日やる1つ）

Claude Codeを開いて、/context というコマンドを打ってみてください。

これだけです。今、AIがどれくらいの情報量を抱えているかが数字で見えます。何も会話していない、まっさらな状態でこの数字が大きいなら、それはあなたの設定ファイルがすでに散らかり始めているサインです。この数字を「今日の自分の部屋の汚れ具合」だと思って眺めてみてください。

1. なぜコンテキストは壊れるのか（部屋の整理という考え方）

Claude Codeは、あなたが何か指示を出すたびに、あらかじめ用意された設定ファイルや過去のやり取りをまとめて読み込んでから答えます。この「読み込む情報のかたまり」がコンテキストです。

ここでよくある誤解が一つあります。「AIには情報を多く渡すほど賢く答えてくれるはずだ」という考え方です。実際は逆に近く、情報を渡しすぎると、AIはどれが今回の指示に関係あるのかを判断しづらくなり、答えの精度が落ちます。部屋の中に不要な物が積み上がっていると、必要な物を探すのに時間がかかるのと同じ構造です。

正しい考え方は「情報を整理し、どこに何を置くかを決めておくこと」です。すべてを一箇所に詰め込むのではなく、性質の違う情報を、性質ごとの置き場所に分けておく。これが次の章で説明する「4層構造」の考え方につながります。

2. 情報の4層構造 ― 何を、どこに置くか

Claude Codeには、情報を置く場所が大きく4種類あります。それぞれ「いつ読まれるか」と「何を書くべきか」が違います。この線引きを理解しておくことが、コンテキスト衛生の土台です。

層 読まれるタイミング 書くべき内容
1. 全体設定ファイル（グローバル） あなたが何をしていても、毎回読まれる どこに何の情報があるかの地図、最低限いつも守ってほしい判断基準
2. プロジェクトの設定ファイル そのプロジェクトの中で作業しているときだけ、毎回読まれる そのプロジェクト固有の口調、やってはいけないこと、前提条件
3. 条件つきのルール置き場 「こういうときはこのルールを見て」と指示したときだけ読まれる 頻度は低いが大事な判断基準（法務・機密・特殊なフォーマット等）
4. 手順書（スキル） 名前と一言説明は毎回読まれ、中身は使うときだけ読まれる 繰り返し使う作業の手順・チェックリスト

ここで大事なのは、1と2は「毎回読まれる」ので、書きすぎるとそれだけでコンテキストを消費し続けるという点です。逆に3と4は「必要なときだけ」読まれる設計なので、細かい情報はできるだけこちらに逃がすのが正解です。

「何をAIに毎回覚えていてほしいか」と「何は必要なときだけ思い出してくれればいいか」。この線引きを最初に決めておくことが、散らからない部屋を保つ一番の近道です。

3. コンテキスト衛生 10ルール（全文）

ここが本体です。上から順に、優先度が高いものから並んでいます。

  1. 全体設定ファイルは短く保つ。 毎回読まれる場所なので、目安として無理なく読み切れる分量に収めます。書きたいことが増えたら、次のルールで別の場所に逃がします
  2. 長くなった判断基準は、条件つきのルール置き場に分離する。 「いつも守る短いルール」は全体設定ファイルに、「特定の場面でだけ必要な長いルール」は別ファイルに分けます
  3. 手順書（スキル）の説明文は、トリガーワードと一言用途だけにする。 説明文は毎回読まれるため、長い前置きを書くとそれだけで情報量が膨らみます。中身の詳しい手順は、使うときにだけ開かれる本体側に書きます
  4. 使っていない外部連携はオフにする。 外部ツールとの連携機能は、オンにしているだけでその仕様書もコンテキストに乗ります。今使っていないものは切っておきます
  5. プロジェクトごとの設定ファイルは、そのプロジェクト固有の話に絞る。 全体に関わる話は1のファイルへ、プロジェクト特有の話はこちらへ、と役割を分けます
  6. /context で定期的に空き具合を確認する。 何も会話していないまっさらな状態で、目安として2割を超えて埋まっていたら整理のサインだと考えます
  7. 会話が長くなったら、区切りをつける。 ずっと同じ会話を続けるのではなく、話題が変わるタイミングで一度リセットする習慣を持ちます
  8. 週に1回、使い方そのものを振り返る。 直近1週間で「思ったのと違う答えが返ってきた」ことがあれば、それは設定ファイルのどこかが古くなっているサインです
  9. 専門的な役割は、専門の担当（エージェント）に持たせる。 何でも一つの窓口に任せるのではなく、役割ごとに担当を分けておくと、それぞれが持つ情報量を絞れます
  10. 見た目やキャラクター設定は、モチベーション維持の道具として割り切って使う。 口調やキャラクターを変えられる機能があれば、続ける力になる範囲で活用してかまいません。ただし機能面の整理を後回しにする言い訳にはしません

この10個は、どれか一つだけを完璧にやるよりも、まず1・2・6・7の4つを押さえるだけで体感が変わります。慣れてきたら残りを足していってください。

4. 週次の見直し運用（10分の回し方）

片付けは一度やって終わりではなく、続けることに意味があります。わどが実践している週次の回し方はシンプルです。

  1. 週の始め、または終わりに10分だけ時間を取る
  2. /context で今の空き具合を確認する
  3. 直近1週間で「なんだかズレた答えが返ってきたな」と感じた場面を思い出す
  4. その原因が、全体設定ファイルの書きすぎか、条件つきルールに逃がすべき話が混ざっていたか、使っていない連携が残っていたかを、10ルールと照らし合わせて特定する
  5. 該当箇所を直す。長くなった部分があれば、条件つきのルール置き場へ移す
  6. 使っていない機能をオフにする

このサイクルを回すたびに、あなたの環境は少しずつ「散らからない部屋」に近づきます。一度に完璧を目指さないことが、続けるコツです。

5. 最新AI（2026年9月時点）での変わり目 ― コンピュータ操作AIとコンテキスト衛生

取得日2026年9月6日時点の情報です。2026年9月3日、OpenAIから新しい大規模モデルが発表されました。この世代の特徴は、文章のやり取りだけでなく「画面の情報を読み取り、許可されたアプリケーションを人間と同じ画面経由で操作できる」という点にあります。申込フォームの記入、資料の作成、ソフトの操作といった作業を、AIが画面を見ながらこなせるようになってきています。

これはコンテキスト衛生の考え方にとって、他人事ではありません。提供元のブログは「画面に表示された内容は、不完全だったり、誤解を招く内容だったり、AIの動きに影響を与えることを意図していたりする可能性がある」という趣旨の注意を明記しています。つまり、AIに画面を見せる・ファイルを読ませるという行為そのものが「何を読ませ、何を読ませないか」という衛生の問題になっているということです。

これまでの10ルールは「あなたが手で書いた設定ファイル」を対象にした話でした。これからは「AIが自分で読み取った画面や外部の情報」も同じ目で整理する必要が出てきます。原則は変わりません。渡す情報を選び、何が指示で何が単なる参考情報かを、AI側にもはっきり伝えることです。

なお、こうしたモデルは段階的に提供が広がっていく形が一般的で、契約しているプランに含まれていても、あなたの画面にはまだ表示されていないことがあります。焦らず、自分の画面で確かめる姿勢で構いません。

最初に投げるプロンプト

今日やる1つ(/context)を実行したあと、次のプロンプトをそのままClaude Codeに投げてみてください。自分の環境の散らかり具合を、AI自身に診断させます。

あなたは私のClaude Code環境の「片付けコンサルタント」です。
以下の観点で、私の全体設定ファイルとプロジェクトの設定ファイルを診断してください。

1. 毎回読まれる場所に、頻度の低い情報が混ざっていないか
2. 長すぎて読み切るのに時間がかかる箇所はどこか
3. 条件つきのルール置き場に逃がした方がよい内容はどれか
4. 手順書(スキル)の説明文が長くなりすぎていないか
5. 使っていなさそうな外部連携が有効になっていないか

指摘は「箇所」と「理由」と「具体的な直し方」の3点セットで、
箇条書きで出してください。

よくある失敗 7つと直し方

  1. 失敗: 全体設定ファイルに、特定のプロジェクトだけの話を書いてしまう。 → 直し方: プロジェクト固有の話は、そのプロジェクトの設定ファイルに移す
  2. 失敗: 「念のため」でどんどん条件やルールを足し続ける。 → 直し方: 足す前に「これは毎回必要か、それとも特定の場面だけか」を自分に問う。特定の場面だけなら条件つきの置き場へ
  3. 失敗: 手順書の説明文に、手順の中身まで書いてしまう。 → 直し方: 説明文はトリガーワードと一言用途に絞り、詳しい手順は本体側に書く
  4. 失敗: 一度作った外部連携を、使わなくなっても放置する。 → 直し方: 月に一度、使っていない連携をオフにする棚卸しの時間を作る
  5. 失敗: /context を一度も確認しないまま数か月使い続ける。 → 直し方: 週次の見直し運用に組み込み、確認そのものを習慣にする
  6. 失敗: 答えがズレ始めても「AIの調子が悪いだけ」で片付けてしまう。 → 直し方: ズレを感じたら、まず自分の設定ファイルの棚卸しを疑う
  7. 失敗: 一度に全部を完璧に整理しようとして、途中で挫折する。 → 直し方: 10ルールのうち優先度の高い数個から始め、少しずつ足していく

安全に使うための注意

  • 個人情報や、公開したくない情報を、設定ファイルや会話の中に不用意に書き残さないでください。設定ファイルは繰り返し読まれる場所なので、一度書いた内容は長く残り続けます
  • 画面の情報を読み取るタイプのAI機能を使うときは、画面に映すものを選んでください。表示されている内容がそのまま指示として解釈されるリスクがあることを、常に頭の片隅に置いておきます
  • 記載の成果は特定の実績であり、同様の成果を保証するものではありません
  • AI(ChatGPT・Gemini・Claudeのいずれでも)にまとめて情報を渡すときは、「これは参考情報です」「これは必ず守る指示です」と役割を分けて伝えると、誤解が起きにくくなります
  • 大事な設定ファイルを直す前には、直す前の内容をどこかにコピーしておく癖をつけてください。整理のつもりで消してはいけない情報を消してしまう事故を防げます
